# Phase 6-0 modern MCP transport closure

Phase 6-0 establishes modern-only MCP `2026-07-28` over stdio and stateless HTTP, with cacheable discovery, per-request metadata, and mandatory HTTP routing headers. The current implementation closes the prior malformed-envelope, stdio database-evidence, and non-finite JSON findings without retaining a legacy initialization path. Supplied execution evidence covers 40 tests, Ruff, the rebuilt image, PostgreSQL revision `002`, database-backed HTTP workflows, and a real stdio database tool call. **Watch for:** no Phase 6-0 blocker remains; **confirmed** recoverable handoff claims remain explicitly deferred to Phase 6-4, so automatic inbound synchronization must stay disabled until then.

**Verdict**: APPROVED

## High-level view

The MCP surface is limited to `server/discover`, `tools/list`, and `tools/call` under protocol `2026-07-28`. Discovery and tool listing are cacheable complete results, with server identity only in namespaced `_meta`.

HTTP binds `MCP-Protocol-Version`, `Mcp-Method`, and the tools-only `Mcp-Name` header to the JSON-RPC body. Raw HTTP and stdio parsing reject malformed JSON constants, while the shared handler independently rejects non-finite identifiers and malformed id-less envelopes.

The stdio smoke starts the real module entry point and invokes `memory_handoff_list` through `ToolDispatcher`; success depends on the migrated `handoffs` table. README and design documentation match this contract and isolate one-shot claim recovery as Phase 6-4 work rather than a gate on the standalone Phase 6-1 client/configuration/credential/package-boundary work.

## Modern discovery and HTTP routing form one contract

`PROTOCOL_VERSION` and `SUPPORTED_VERSIONS` expose only `2026-07-28`; removed `initialize`, `notifications/initialized`, and `ping` behavior has no compatibility route. `server/discover` contains `resultType`, supported versions, capabilities, instructions, `ttlMs`, and `cacheScope`, while `serverInfo` is absent from the result root and present only at `_meta["io.modelcontextprotocol/serverInfo"]`. Tests pin the literal version and full discovery shape.

The HTTP endpoint rejects missing or mismatched protocol/method headers with the reserved routing error, requires `Mcp-Name` exactly for `tools/call`, rejects unsupported versions separately, and returns `MCP-Protocol-Version` on controlled MCP responses. The HTTP E2E sends these headers for discovery and real tool calls, matching README and design guidance.

## Malformed JSON-RPC stays inside controlled error paths

Envelope validation precedes notification classification, so an id-less object with an invalid JSON-RPC envelope returns `-32600` with a null identifier instead of disappearing. Present identifiers are limited to strings or finite non-boolean numbers.

Direct-handler regressions cover `NaN`, positive infinity, and negative infinity as invalid IDs. Raw stdio and HTTP parsing reject non-standard constants through `parse_constant` and return `-32700` before dispatch or response serialization, closing the prior transport-specific failure mode.

## Stdio evidence crosses the production PostgreSQL boundary

`tests/stdio_e2e_smoke.py` invokes `python -m isekai_memory.main --mode stdio` with the configured database URL and calls `memory_handoff_list`. `run_stdio` initializes the production pool and constructs `McpStdioServer(ToolDispatcher(settings))`; the dispatcher reaches the handoff service, and the asserted non-error `structuredContent` requires the migrated handoff query to succeed.

The supplied run evidence reports PostgreSQL 16 revision `002`, the stdio database call, HTTP artifact/policy/handoff flows, all 40 tests, Ruff, and a rebuilt Docker image passing. Independent local rerun was unavailable because this host has only Python 3.9 and lacks pytest and Ruff; implementation paths and assertions were inspected directly.

## Phase 6-4 retains claim recovery ownership

The design keeps handoff pull as a one-shot claim without lease, acknowledgement, or replay and prohibits direct `ContextService` claiming. Phase 6-1 may begin while automatic inbound synchronization remains disabled pending Phase 6-4 recovery semantics.
