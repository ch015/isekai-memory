# Phase 6-0 malformed-request and stdio database fixes

The re-review confirms that malformed id-less envelopes now receive `-32600`, ordinary invalid identifier types are rejected before notification classification, and the stdio smoke now crosses the production dispatcher into PostgreSQL through `memory_handoff_list`. Discovery assertions also pin the literal protocol version, capabilities, and instructions, closing the prior coverage gap. One edge of the original identifier blocker remains: non-finite floating-point IDs are admitted even though they are not JSON numbers, producing invalid stdio output and an HTTP serialization failure. Standalone Phase 6-1 `MemoryClient`, configuration, and credential work can begin because this parser issue does not change its API or trust boundary, but Phase 6-0 should not close yet. **Watch for:** **[Medium, confirmed, Phase 6-0 blocker]** `NaN` and infinite IDs still bypass identifier validation; **[Informational, confirmed, later handoff phase]** one-shot claims remain intentionally non-recoverable and automatic inbound synchronization must stay disabled.

**Verdict**: NEEDS_CHANGES

## High-level view

Envelope validation now precedes notification classification, correcting the suppression defect. The numeric-ID branch remains too broad: Python’s JSON decoder accepts `NaN` and infinities, and the handler accepts every non-boolean `float`.

The stdio E2E now sends `tools/call` for `memory_handoff_list` through `python -m isekai_memory.main --mode stdio`. That path executes an update/select transaction against `handoffs`, so `database_tool_call=true` depends on a migrated table rather than database connectivity alone.

HTTP and documentation remain aligned around stateless MCP 2026-07-28. Recoverable handoff claiming remains a documented later-phase gate for automatic inbound synchronization; it is separate from Phase 6-0 and does not block standalone Phase 6-1 client/configuration/credential work.

## Non-finite numeric IDs remain outside the validation boundary

`McpProtocolHandler.handle` now checks the JSON-RPC version and string method before classifying notifications, and rejects `None`, booleans, arrays, and objects when an `id` is present. That closes the reported malformed-envelope cases covered in `tests/test_server.py`.

The numeric predicate accepts every Python `float`, including `NaN`, positive infinity, and negative infinity. Both transports parse with the standard library’s permissive `json.loads`, which accepts those tokens despite their exclusion from the JSON grammar. A `tools/list` request with `"id": NaN` reaches routing and returns `id: NaN`; stdio serializes that non-JSON token, while Starlette’s `JSONResponse` raises `ValueError: Out of range float values are not JSON compliant`. This is **[Medium, confirmed, Phase 6-0 blocker]** because malformed input escapes the controlled `-32600` or parse-error path.

Reject non-finite floats with `math.isfinite` in the ID predicate, or make both JSON decoders reject non-standard constants and map them to `-32700`. Add direct handler and transport cases for `NaN` and infinities because the serializers fail differently.

## Stdio evidence now depends on the handoffs table

The smoke launches the real module entry point and sends a `memory_handoff_list` call for an isolated project. `ToolDispatcher` routes it to `list_handoffs`, whose transaction updates expired rows and selects pending rows from `handoffs`; the asserted empty structured result cannot succeed against a connected but unmigrated database. This closes the prior **[Medium, confirmed]** stdio E2E blocker while keeping the result deterministic relative to the HTTP E2E’s separate `project-1` data.

## Recoverable claim work remains outside Phase 6-0

`docs/design.md` states that pull is a one-shot conditional claim without a lease, acknowledgement, or replay token, and blocks direct `ContextService` claiming until recovery exists. This is **[Informational, confirmed, later handoff phase]**, not a protocol-fix regression or a blocker for standalone Phase 6-1 `MemoryClient`, configuration, or credential work. Automatic inbound synchronization must remain disabled until that later contract is implemented.
