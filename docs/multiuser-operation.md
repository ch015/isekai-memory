# 여러 사용자와 작업 공유 — schema 020

Memory 서버와 PostgreSQL 하나를 공동으로 사용하고, 각 사용자는 자신의 ADE 작업 폴더와 인증을 유지한다.
로컬 State DB나 인증 파일은 공유하지 않는다. 이 변경에는 별도 파일 서버나 동기화 서비스가 필요 없다.

## 권한과 수신자

- 프로젝트 소유자가 기존 `memory_project_assign`으로 사용자를 `read` 또는 `write`에 할당한다.
- 등록된 프로젝트에서는 프로젝트 전용 토큰도 현재 멤버십을 확인한다. `read`로 바꾸면 쓰기가,
  `remove`하면 이후 읽기·쓰기가 차단된다. 이미 받은 파일이나 실행 중인 작업의 메모리까지 회수하지는 않는다.
- `projects` 범위 토큰 사용자는 자신이 소유하거나 `write`로 할당된 프로젝트의 인계 수신자가 될 수 있다.
  소유권이나 멤버십만으로 토큰의 원래 범위보다 큰 권한을 얻지 않는다.
- 서버 디렉터리에 아직 등록하지 않은 프로젝트는 기존 프로젝트 전용 토큰 규칙을 유지한다.
- 분류값(`internal` 등)은 컨텍스트 선택 한도이며 사용자별 비밀 등급 ACL은 아니다.
  서로 읽으면 안 되는 자료는 멤버십이 다른 프로젝트로 분리한다.

## 무엇을 공유하는가

| 대상 | 기존 경로와 의미 |
| --- | --- |
| 완료 결과 | Task/Result 요약·참조 인계. 파일 본문은 포함하지 않는다. 일반 자동 인계는 단일 소비자이며 송신자 자신의 항목은 자동 수신에서 제외한다. |
| 팀이 반복해서 참고할 경험 | 승인된 Project Experience를 검색한다. 일반 인계 한 건을 팀 전체 방송으로 해석하지 않는다. |
| 지정 사용자에게 이어할 작업 | 기존 continuity 정책의 수신자/백업과 독립된 인수·확인 절차를 사용한다. |
| 미완료 파일 | Git은 기준 커밋과 변경분, 일반 폴더는 허용 파일 스냅샷을 전달한다. 수신자는 별도 폴더에서 복원한다. 원래 파일은 덮어쓰지 않는다. |
| Git 없는 프로젝트 가져오기 | 프로젝트 구성과 빈 작업 폴더를 준비한다. 파일은 별도의 명시적 체크포인트 공유로 받는다. |
| 자료·결과·작업 이력 | 구성원 범위의 요약·참조와 출처를 저장·검색한다. [schema 020 운영 안내](project-sharing.md)를 따른다. |

서로 다른 PC의 Lock은 설치 ID·계정에 따라 다르다. 새 클라이언트는 검증된 로컬 generation에서
`compatibility_digest`를 계산해 패키지 내용과 프로젝트 정책이 같은지 비교한다.
Task/Result, 체크포인트, 검색 인용의 송신자 Lock은 출처로 그대로 보존한다.
수신자의 로컬 Lock은 별도 Evidence로 결박하며, 인수 자체가 도구 실행 승인이나 로컬 Gate 통과를 뜻하지 않는다.
호환 digest가 없는 과거 기록은 기존의 정확한 Lock 일치 조건을 유지한다.

`memory_handoff_list`는 기본/최대 100개이며 `after_id`로 이어 조회한다.
`exclude_own=true`는 인증된 사용자를 기준으로 자신이 보낸 항목을 제외한다.
새 자동 수신기는 한 번에 최대 4페이지를 훑고 기존 `max_batch` 이내에서 처리한다.
portable 검색은 `memory_search.compatibility_digest`를 선택적으로 사용하며 해당 인용은 schema 2로
호환 digest까지 결박한다. 기존 검색은 schema 1을 유지한다.

## 기존 서버 갱신

1. DB 백업 후 기존 요청을 멈추고 서버 코드를 갱신한다. `alembic upgrade head`로 020을 적용한다.
2. 등록된 프로젝트의 소유자가 계속 사용할 기존 토큰 사용자를 명시적으로 할당한다.
   기존 토큰만 보유하고 멤버십이 없던 사용자는 이제 접근할 수 없다. 제거된 사용자를 자동 복구하지 않는다.
3. 서버 `/ready`가 `schema_revision: "020"`인지 확인한 뒤 ADE 내장 엔진을 함께 갱신한다.
   구 서버는 새 선택 필드를 거부할 수 있으므로 서버부터 갱신한다. 기존 outbox payload는 변경하지 않는다.
4. 각 사용자로 프로젝트 조회→결과 수신→필요한 체크포인트 준비를 확인한다.

018은 기존 행·ID·payload를 보존한다. 새 portable handoff가 저장된 뒤 017로 내리는 작업은
출처 결박 손실을 막기 위해 거부한다. 강제 컬럼 삭제로 되돌리지 않는다.

Compose 기본 포트는 이제 `127.0.0.1`이다. 팀 접속은 기존 HTTPS 프록시 또는 암호화된 터널을 통해
제공한다. 별도 네트워크 인터페이스 바인딩이 필요한 경우 `ISEKAI_LOCAL_BIND_HOST`를 명시한다.
토큰을 전송하는 원격 평문 HTTP는 통신 보호를 제공하지 않는다.

## 검증

`tests/test_multiuser_postgres.py`는 실제 PostgreSQL에서 멤버십 회수·디렉터리 수신자·인용 무결성·페이지 조회를,
`tests/test_multiuser_migration.py`는 017 데이터 보존·빈 downgrade·데이터가 있는 downgrade 거부를 검사한다.
`tests/run_local_e2e.py`는 현재 스키마와 도구 목록을 기준으로 실제 HTTP/stdio를 검사한다.
ADE의 `tests/manual/memory-sharing.py`는 서로 다른 계정·Lock을 가진 두 설치와 실제 HTTP 서버에서
결과 수신·기억 검색·미완료 파일 복원·권한 회수를 검증한다. 모두 명시적으로 지정한 폐기 가능한 DB를 사용한다.
