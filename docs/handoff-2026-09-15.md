## 진단에서 확인한 미완성 지점

1. Core 연결 등록은 로컬 JSON 저장일 뿐 Memory에 프로젝트를 등록하지 않는다.
2. 현재 서버 82개 도구에는 업무 프로젝트 등록·전체 목록 API가 없다.
   memory_repo_list는 Foundation/Preset 배포 저장소이지 사용자 프로젝트 목록이 아니다.
3. 서버 auth_enabled=false는 모든 요청을 local-stdio로 처리한다.
4. 인수 대상 목록/적격성은 access_tokens에 의존한다. 공용 키만 만들면 M8이 완성되는 것이 아니다.
5. Project의 Memory 기능 opt-in·서버 관측 정책은 콘솔 연결과 별개다.
6. 현재 이벤트는 일부 협업 변경의 프로젝트별 feed이며 전역 업무 활동 feed가 아니다.
7. 임의 project_id 조회가 ready/0건을 반환해도 서버 등록 완료 증거가 아니다.

## 환경 상태와 주의

- 원격 테스트 대상: http://192.168.10.21:8100/mcp.
- 연결 성공 후의 구조 점검에서는 접속 타임아웃이 발생했다. 주소 가용성은 다시 확인한다.
- 원격 서버 인증 해제는 사용자에게 옵션만 안내했다. 이 PC에서 원격 Compose를 변경하지 않았다.
  후속 성공 응답 당시 원격은 무인증 MCP를 허용했다.
- Git의 compose.yaml은 아직 ISEKAI_MEMORY_AUTH_ENABLED: "true"이다.
  docker compose up만으로 공용 키가 자동 발급되거나 Core에 자동 등록되지 않는다.
- 현재 auth_static_token 설정은 deprecated이며 공용 키 구현으로 재사용하면 안 된다.
- 로컬 임시 조회 조직/프로젝트 ID local / isekai-memory는 기존 서버 등록에서 가져온 값이 아니다.
  사용자 설정 파일·키·DB·감사 결과물은 커밋에 포함하지 않는다.
- 192.168.* 회사 LAN 주소는 집에서 VPN 등 경로가 없으면 사용할 수 없다.

## 집에서 재개

```sh
# 각 저장소에서 원격 이름과 현재 브랜치를 먼저 확인
git remote -v
git status --short
git branch --show-current

# ch015/isekai-memory의 main을 추적하는 깨끗한 작업 복사본에서
git pull --ff-only
```

Memory의 현재 대상 원격은 https://github.com/ch015/isekai-memory.git / main이다.
이 작업 PC의 origin은 to-nexus이고 upstream은 예전 Hub 주소이므로 이름만 보고 push하지 않는다.
집의 origin이 다른 저장소라면 ch015 원격을 별도 등록·fetch하고 전용 작업 복사본을 사용한다.
서로 다른 초기 이력이면 force/reset/unrelated-history merge를 무작정 수행하지 않는다.

Core도 기존 to-nexus/isekai-core 또는 dotwin7/isekai-core의 master를 갱신한다.
최종 게시 대상/SHA는 작업 완료 메시지와 각 원격 git log에서 확인한다.
이전 .venv/uv tool 설치와 프로세스는 pull만으로 갱신되지 않는다.

먼저 M10 계획의 서버/API 계약을 구현하고, 화면의 수동 연결 추가만 반복하지 않는다.
DB migration은 구현 시 최신 head를 확인해 가산적으로 작성하고 기존 013 데이터를 보존한다.
회사 운영 서버 배포, 공용 키 실제 발급, GitHub credential 공유는 이 문서 작성으로 실행되지 않는다.
