# 프로젝트 자료·작업 이력 공유 — schema 020

ADE U87은 생성 시 Git/일반 로컬을 명시적으로 선택하고 폴더 가져오기 시 실제 종류를 자동 판별한다.
별도 서버 API는 추가하지 않고 아래 source_kind 및 기존 프로젝트 디렉터리를 사용한다.

Memory는 기존 PostgreSQL 하나에서 프로젝트 구성원, 자료·결과·작업 이력과 체크포인트를 관리한다.
별도 벡터 DB, 파일 동기화 서비스, 메시지 브로커는 추가하지 않는다. ADE 내장 엔진이 현재 클라이언트다.

## 프로젝트 종류

`memory_project_register.source_kind`는 `git`, `directory`, `unknown`이다. `git_url`은 선택적인
팀 공유 clone 주소다. 주소 없는 Git 프로젝트도 `git`으로 표시할 수 있다. 주소가 있으면 종류는 `git`이다.
019 이전의 주소 없는 행은 `unknown`으로 유지한다. 주소가 없다는 이유만으로 비 Git으로 추정하지 않는다.
ADE는 현재 열린 폴더를 별도 관측하므로 서버에 등록된 원본 정보와 각 PC의 실제 폴더 종류는 다를 수 있다.

## 자료와 이력

| MCP 도구 | 권한·동작 |
| --- | --- |
| `memory_project_record_put` | write 구성원/소유자가 activity/material/result를 저장한다. 인증 사용자가 작성자다. UUID·작성자·프로젝트·내용을 결박한다. 같은 요청 재시도는 중복 저장하지 않는다. |
| `memory_project_record_list` | 현재 구성원이 자신의 프로젝트 안에서 검색·조회한다. 종류/Unit/이전 sequence 필터, 기본 30·최대 50건이다. |
| `memory_project_record_remove` | 작성자 또는 소유자가 본문·제목·참조를 지운다. UUID/digest tombstone은 남겨 늦은 재시도가 삭제된 자료를 복원하지 못하게 한다. |

put/remove에는 `expected_actor`가 필수이며 list에서도 지정할 수 있다. 연결 계정이 바뀐 전송은 실패한다.
등록 프로젝트의 멤버십을 트랜잭션 안에서 다시 확인한다. 권한 회수 후 다음 조회·전송은 거부한다.
record ID가 다른 프로젝트나 작성자와 충돌하면 기존 내용을 노출하거나 덮어쓰지 않는다.

제목은 200자, 본문은 8,192자, 참조는 20개이며 직렬화 요청은 48 KiB 이내다. 상대 경로와 인증정보 없는 HTTPS 주소만 참조로 받으며
링크를 서버가 다운로드하지 않는다. 알려진 개인키·일부 토큰 패턴을 거부하지만 일반적인 비밀정보 탐지를
보장하지는 않는다. 구성원에게 공유할 수 있는 요약을 보내야 한다.

검색은 PostgreSQL full-text와 이스케이프한 부분 문자열 검색을 함께 사용한다. 한국어와 `%` 같은
리터럴 검색도 지원한다. `memory-project:<UUID>`, 작성자, 생성 시각, payload digest를 반환한다.
응답은 `reference_only`, `no_store`이며 사용자/프로젝트 간 결과 캐시를 공유하지 않는다.
검색한 텍스트는 참고 자료다. 프롬프트의 지시나 실행 승인으로 취급하면 안 된다.
현재 기록은 명시적으로 삭제할 때까지 보관한다. 별도 자동 보존 기간이나 벡터 임베딩은 없다.

ADE의 자동 이력은 명시적으로 켠 이후 Unit/PhaseAttempt/Gate 상태 변경을 투영한다.
원시 대화·프롬프트·명령 출력·일반 파일 수정은 자동 전송하지 않는다. 자료·결과 요약은 명시적 입력이다.
기존 ADE 서비스가 최대 255개의 계정별 로컬 대기열을 재시도하며, 자동 이력은 저장된 커서부터
계속 투영한다. 전송 성공 전 로컬 접수만으로 원격 공유 완료를 표시하지 않는다.

## 비 Git 파일

continuation schema 1은 기존 Git 기준 커밋을 유지한다. schema 2는
`repository: {source_id, kind: "directory"}`와 파일 내용/digest를 사용하며 가짜 커밋을 만들지 않는다.
명시적 로컬 opt-in과 공통 정책의 허용 경로가 모두 필요하다. 캡처 한도는 100개 파일·1 MiB이고,
보호 경로·심볼릭 링크·하드 링크·자격정보·수집 중 변경은 실패 처리한다. 허용 범위 밖 파일은 읽지 않는다.
schema 2에서 파일 삭제 명령은 허용하지 않는다. 수신자는 새 별도 폴더에 복원하고 기존 파일을 보존한다.
공유 프로젝트 가져오기는 여전히 구성만 복원한다. 실제 파일은 지정한 수신자에게 체크포인트로 전달한다.

## 갱신과 검증

1. DB 백업, 요청 중단, `alembic upgrade head`, 새 서버 실행 후 `/ready`의 revision `020`을 확인한다.
2. 등록된 프로젝트의 사용자 멤버십을 확인한다. 018의 멤버십 집행 변경은 기존 운영 안내를 따른다.
3. 새 ADE를 적용하고 사용자가 자동 이력 및 파일 공유를 선택한다. 진행 중 Unit/Lock을 자동 이관하지 않는다.
4. 읽기/쓰기 사용자 각각 자료 검색과 파일 인수를 확인한 뒤 팀에 사용을 안내한다.

019는 기존 프로젝트 종류를 보존하며, 020은 새 테이블을 추가한다. 공유 자료가 존재하면 020 downgrade를
거부한다. 새 schema 2 continuation을 구 클라이언트가 읽을 수 있다고 가정하지 않는다.
현재 작업은 개발 검증이며 운영 DB·서버·설치형 앱은 교체하지 않았다.
